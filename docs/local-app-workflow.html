Customer journey

From first visit to delivered

Each step lists what the customer sees, what happens behind the scenes, and the API involved.

1

Open the site → choose a location

Customer

  • Sees the landing page.
  • Taps Use my current location, or Find my address on the map, or a saved address (if signed in).
  • A category tile picked first is remembered (?v=GROCERY) and opens after the location is set.

App / server

  • Browser GPS → lat/lng rounded to 6 decimals.
  • Signed in: area name from reverse geocoding; guests see "Current location".
  • Saved as dz-local-location; the page switches to the shop list.

API

GET /v1/geo/reverse login
Map search uses Google Places in the browser (or OpenStreetMap fallback).

2

Browse shops near you

Customer

  • Searches ("basmati", "biryani") or filters by Food, Groceries, Medicines, Lab tests, Local shops.
  • Sees ETA, distance, ₹30 fee, rating, Busy / Closed · opens at.

App / server

  • Only LIVE / LIMITED shops.
  • Only shops that deliver to the address (shop's radius; LIMITED: max 2 km). Home delivery only — no self-pickup.
  • Search matches shop name, cuisines and product names.
  • Labs show "Book a slot" (no fee, no ETA).

API

GET /v1/local/stores?lat&lng&vertical&q public

3

Open a shop → add to cart

Customer

  • Scrolls categories, searches in the shop, "Veg only".
  • Taps ADD; dishes with sizes / add-ons open the options sheet ("Pick 1", "Up to 3").
  • Uses − / + on the item; green cart bar shows "3 items · ₹398".

App / server

  • Cart holds one shop; adding from another asks "Start a new cart?".
  • Same item with different options = separate line.
  • "Only N left" shown for 1–5 in stock; never the real count. Qty capped by stock and per-order limit (default 20).

API

GET /v1/local/stores/:idOrSlug?lat&lng public
Cart itself is on the device.

4

Go to cart → log in or sign up

Customer

  • Guest sees "Log in to place your order" (cart is kept).
  • Log in: mobile → OTP. Sign up: name, mobile, optional email, tick terms → OTP → "Verify and create account".

App / server

  • OTP verify with app: 'LOCAL' creates the user (if new) and a customer row.
  • Sign up saves name / email / WhatsApp opt-in; an existing number keeps its name; an email used elsewhere is skipped (409 EMAIL_TAKEN).
  • New number via "Log in" → welcome step asks for the name.
  • Returns to the page in ?next (here /cart).

API

POST /v1/auth/otp/request
POST /v1/auth/otp/verify
PATCH /v1/local/me login

dev the code is shown on screen while SMS isn't connected.

5

Add the delivery address

Customer

  • Drags the pin to the building entrance.
  • Types house / flat; street, landmark, PIN, city, state are filled from the pin.
  • Label Home / Work / Other; optional "Someone else will receive it".

App / server

  • First address becomes the default.
  • Pin within 300 m of a saved address → that address is picked automatically.
  • Delete is a soft delete (old orders keep it). Max 20 addresses.

API

GET / POST /v1/local/me/addresses
PUT / DELETE /v1/local/me/addresses/:id login

6

Checkout → place the order

Customer

  • Checks the delivery address, adds a note.
  • Sees Item total, Delivery fee ₹30, To pay, and “No platform fee · No packaging fee”.
  • Picks UPI, card or net banking.
  • Taps Pay ₹428 & place order.

App / server

  • Server re-prices the basket (quote) and lists anything blocking the order (see Rules).
  • Place uses one Idempotency-Key per attempt → a double tap makes one order.
  • Goes through the same OrdersService.create as every channel: stock is held, 4-digit codes made, shop alerted, auto-accept if the shop has it on.

API

POST /v1/local/cart/quote
POST /v1/local/orders login (channel LOCAL_WEB, paymentMode: UPI | CARD | NETBANKING)

7

Track the order

Customer

  • "Order placed!" → steps Placed · Preparing · On the way · Delivered.
  • Yellow box with the 4-digit code for the rider.
  • Call rider / call shop; Cancel order while the shop hasn't accepted.

App / server

  • Screen refreshes every 8 s while the order is active (live socket + push in L3).
  • Shop accepts / prepares / marks ready in the Partners app; the rider hands over with the shop's code, then delivers with the customer's code.
  • Codes disappear once the order is finished.

API

GET /v1/local/orders/:idOrNumber
POST /v1/local/orders/:id/cancel
GET /v1/local/orders login

8

At the door

Customer

  • Shares the code with the rider (already paid online).
  • Groceries & local shops: checks the items while the rider waits up to 5 minutes; hands back damaged / wrong items.

App / server

  • Refund straight away to the payment method; bill and GST report reduced; shop told "items coming back".
  • Return window closes after 5 min, or when the customer is happy.

API

Rider side today runs from Admin (/v1/admin/orders/:id/returns). Customer-side request comes in L4.

Rules

The rules behind each step

Which shops show

  • Status LIVE or LIMITED only.
  • Delivers if distance ≤ shop's delivery radius; LIMITED shops max 2 km.
  • Sort: open → delivers here → nearest.
  • ETA = prep time (+10 min when Busy) + travel time.

What an item shows

  • Hidden if deleted or switched off; "Sold out" if paused or no stock.
  • "Only N left" for 1–5 units.
  • Max qty = min(per-order limit or 20, stock left).
  • MRP struck through when higher than price; "% off" from 5%.
  • Rx tag for prescription medicines; sample / fasting / report time for lab tests.

Bill

  • Items: price + size difference + add-ons, × qty.
  • Delivery fee: flat ₹30.
  • No platform fee and no packaging fee on app orders.
  • Prices include GST; the shop's GST bill is printed from the Partners app.

What the shop sees

The order arrives in the Partners app like any other (channel LOCAL_WEB): first name only, masked phone, area + PIN, note, items, totals. The customer's codes are never sent to the shop.

What the customer sees

Their own orders only (another customer's order → 404). Door code for the rider, shown while the order is active. Rider first name and phone once assigned.
